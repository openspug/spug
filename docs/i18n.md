# Internationalization (i18n)

Spug ships with a Simplified Chinese and an English interface. Users switch
languages from the globe icon in the header (or on the login page); the choice
is stored in `localStorage` under `spug:language` and the page reloads so that
Ant Design and moment pick up the new locale too.

## How it works

Chinese is the source language: the original Chinese text **is** the translation
key. `t()` looks the key up in the English dictionary when the UI is in English
mode, and returns the key unchanged in Chinese mode. That means the Chinese UI
can never regress from a missing or wrong translation.

```js
import { t } from 'libs';

t('新建')                       // zh: '新建'          en: 'New'
t('确定要删除【{}】?', name)     // {} placeholders are filled in both languages
```

Only user-visible text is wrapped. Values sent to or compared against the
backend (`<Select.Option value="branch">`, `status === '3'`, localStorage keys)
stay untouched.

## Frontend layout

| Path | Purpose |
| --- | --- |
| `spug_web/src/libs/i18n.js` | `t()`, `getLanguage()`, `setLanguage()`, `langMode`, `isEN` |
| `spug_web/src/locales/en/index.js` | merges every module dictionary |
| `spug_web/src/locales/en/base.js` | shared glossary, merged **last** so common terms stay consistent |
| `spug_web/src/locales/en/<module>.js` | per-module dictionaries (host, deploy_app, pipeline, …) |

Add a translation by putting the exact Chinese string as the key in the
dictionary of the module you are working on. If the term is already in
`base.js`, do not redefine it — `base.js` wins on conflicts.

## Backend messages

API error messages and the `*_alias` display values of model choices are
translated in `spug_api/libs/locale.py`:

- `MESSAGES` — exact-match error strings.
- `_PATTERNS` — regexes for messages built with f-strings, e.g.
  `已存在的主机名称【web-01】`.
- `CHOICES` — display values of model field choices (deploy status, monitor
  type, …), returned to the client through `status_alias`, `type_alias`, etc.

`libs/middleware.py:TranslateMiddleware` applies them when the request carries
`X-Language: en` (the frontend sets this header on every `/api/` call). Requests
without the header — or with `zh` — are passed through untouched.

## Adding a new language

1. Copy `spug_web/src/locales/en/` to `spug_web/src/locales/<lang>/` and
   translate the values.
2. In `libs/i18n.js` load the dictionary for that language and extend
   `getLanguage()` / the language menu in `layout/Header.js` and
   `pages/login/index.js`.
3. Map the language to an Ant Design locale and a moment locale in
   `spug_web/src/index.js`.
4. Optionally add a matching dictionary next to `libs/locale.py` for backend
   messages and dispatch on the `X-Language` value in `TranslateMiddleware`.
